# Запуск сервера замовлень (Hetzner, ~6 €/міс)

Що вийде: сайт приймає ім'я + фото + email → сервер сам озвучує ім'я в ElevenLabs, вписує його в книгу, ставить фото в портрет, рендерить 1080p → ви дивитесь ролик в адмінці й натискаєте «Підтвердити» (або вмикаєте автонадсилання) → клієнт отримує лист із посиланням.

## 1. Сервер
1. Зареєструйтесь на hetzner.com → Cloud → **Add Server**.
2. Location: Falkenstein або Helsinki. Image: **Ubuntu 24.04**. Type: **CPX31** (4 vCPU, 8 GB, ~13 €) для швидкого рендеру або **CPX21** (3 vCPU, 4 GB, ~7 €) для старту.
3. Додайте свій SSH-ключ, створіть сервер, скопіюйте його IP.

## 2. Домен
У DNS вашого домену додайте запис **A**: `api` → IP сервера. Сайт буде на `https://api.ваш-домен` (сертифікат HTTPS ставиться сам).

## 3. Встановлення (один раз)
```bash
ssh root@IP
curl -fsSL https://get.docker.com | sh
git clone https://github.com/polgroup222/site.git && cd site/service
cp .env.example .env && nano .env        # заповніть домен, ADMIN_TOKEN, ключі ElevenLabs
mkdir -p runtime/master
```
Завантажте мастер-відео з VN зі свого Mac:
```bash
scp master.mp4 root@IP:~/site/service/runtime/master/master.mp4
```
Запуск:
```bash
docker compose up -d --build
curl https://api.ваш-домен/health          # має відповісти {"ok":true,...}
```

## 4. Сайт
У `index.html` впишіть адресу сервера: `<meta name="order-api" content="https://api.ваш-домен">`.
Поки там порожньо, форма працює в демо-режимі.

## 5. Щоденна робота
- Адмінка: `https://api.ваш-домен/admin/login` (або ваша прихована адреса з `ADMIN_LOGIN_PATH`) → вставте ADMIN_TOKEN у поле (один раз, далі пам'ятає 30 днів). Кнопка «Вийти всюди» закриває адмінку на всіх пристроях.
- `PAYMENT_MODE=manual`: нове замовлення чекає «Оплачено → у чергу». Коли підключимо оплату, це буде автоматично.
- Після рендеру ролик з'являється в адмінці. «Підтвердити і надіслати» → клієнту йде лист (якщо заданий `RESEND_API_KEY`), або скопіюйте посилання «сторінка клієнта» вручну.
- Ролик із зауваженнями (обличчя не знайдено, незнайоме ім'я тощо) ніколи не йде клієнту сам.

## Оновлення мастера чи коду
```bash
cd ~/site && git pull && cd service && docker compose up -d --build
```
Новий мастер: замініть `runtime/master/master.mp4`; якщо змінились секунди книги/портрета, поправте `master/master.json`.

## Що де лежить
- `runtime/orders/<id>/` — фото, order.json, готовий `out/video.mp4`.
- `runtime/voice_cache/` — озвучені імена (кожне ім'я генерується лише раз).
- Бекап: достатньо копіювати папку `runtime/`.

## Агенти-помічники (28.11.2026)
1. **Контроль замовлень** (`server/agents.js`, `tools/photo_check.py`): після оплати, перед рендером, перевіряє оплату, фото (одне обличчя, не замале, не темне, не розмите) та ім'я. Якщо щось не так, статус «Чекає вашого OK»: кнопка **OK → у рендер** в адмінці. Голос ElevenLabs на таке замовлення не витрачається, поки ви не натиснете OK.
2. **Перевірка готового відео** (`tools/video_check.py`): після рендеру порівнює ролик з мастером: тривалість, чи читається файл, зайві чорні кадри або тиша, гучність і хрип, чи звучить ім'я, чи змінилась сторінка книги, чи стоїть фото в рамці з обличчям. В адмінці список ✓/✗ і два кадри (книга, портрет). Клієнту ролик іде лише після вашого «Підтвердити».
3. **Сторож сервера** (`tools/watchdog.py`): запускається на сервері (не в контейнері) кожні 10 хв, пише `runtime/watchdog.json`.
   ```bash
   echo '*/10 * * * * root /usr/bin/python3 /root/site/service/tools/watchdog.py >> /var/log/cestitam-watchdog.log 2>&1' > /etc/cron.d/cestitam-watchdog
   ```
- Telegram: у `.env` додайте `TG_BOT_TOKEN=` і `TG_CHAT_ID=` (вставляєте самі, у чат не надсилати), потім `docker compose up -d`. Ранкова зведення щодня о 08:00 за Києвом (`OWNER_TZ`, `SUMMARY_HOUR`).
- Без Telegram усе видно в блоці «Проблеми» вгорі адмінки.

## Звіт і Google-таблиця (28.11.2026)
- Сторінка «🤖 Агенти» → розділ «📊 Звіт за день». О 21:00 за Києвом звіт зберігається в `runtime/reports/РРРР-ММ-ДД.json` (у Telegram не йде; ранкова зведення о 08:00 лишається).
- Google-таблиця лише оплачених замовлень: інструкція в `tools/google-sheet.gs`. У `.env`: `SHEET_WEBHOOK=…/exec` і `SHEET_SECRET=…`. Рядок оновлюється при кожній зміні статусу; о 21:00 таблиця повністю звіряється.

## Безпека (28.11.2026)
- Сервіс у контейнері працює **не від root** (користувач node). При старті він сам робить папку `runtime/` своєю (`docker-entrypoint.sh`). Сторож і бекап на сервері далі працюють від root і віддають свої журнали тому ж власнику.
- ImageMagick обмежений (`config/imagemagick-policy.xml`): вимкнені небезпечні формати (SVG, PDF, PostScript, мережа, читання файлів через `@`). Якість фото не змінюється.
- Вхід клієнта на `/porudzbina`: **телефон або email + повний номер з літерами** (KM-00006). Не більше 5 спроб за 10 хв і 20 невдалих на добу на один телефон/email.
- У заявці тепер обовʼязковий телефон (і email на сайті).
- Адмінка: токен вводиться у форму (не в адресу), мінімум 24 символи, не більше 10 спроб на годину з IP; про кожен вхід і невдалу спробу приходить Telegram.
- `PAYMENT_MODE=mock` «оплачує» лише тестові замовлення. Якщо стоїть `none` або `MOCK_PAY_ALL=1`, у CRM горить попередження.
- Заголовки безпеки (HSTS, заборона iframe, CSP з разовим nonce) — у `Caddyfile` і в сервері.
- Бекап поза сервером: задайте `BACKUP_PASS` у `.env` → щоденний бекап шифрується і йде в Telegram.
- Нові замовлення зупиняються (503), якщо на диску менше 3 ГБ.
- Адмінка прихована: без входу будь-яка адреса `/admin…` відповідає «не знайдено». Адресу входу можна змінити: `ADMIN_LOGIN_PATH=/admin/своє-слово`.
- Токен адмінки можна тримати в `.env` лише як хеш (`ADMIN_TOKEN_SHA256`).
- CORS: `ALLOWED_ORIGINS` лише ваш домен або порожньо (сайт і сервіс на одному домені).
- Оновлення системи й образів: `docker compose build --pull && docker compose up -d --force-recreate` (у Dockerfile також `apt-get upgrade`).
